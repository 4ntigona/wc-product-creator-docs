O WC Product Creator oferece **suporte completo a formatos numéricos brasileiros** (PT-BR) e americanos (EN-US), permitindo que usuários digitem valores usando vírgula ou ponto como separador decimal.

## Diferenças Regionais

### Brasil (PT-BR)

- **Separador decimal:** vírgula (`,`)
- **Separador de milhares:** ponto (`.`)
- **Exemplos:**
  - `10,5` = dez vírgula cinco
  - `1.234,56` = mil duzentos e trinta e quatro vírgula cinquenta e seis
  - `-0,5` = menos zero vírgula cinco

### Estados Unidos / Internacional (EN-US)

- **Separador decimal:** ponto (`.`)
- **Separador de milhares:** vírgula (`,`)
- **Exemplos:**
  - `10.5` = ten point five
  - `1,234.56` = one thousand two hundred thirty-four point fifty-six
  - `-0.5` = minus zero point five

<Aside type="tip">
**Flexibilidade:** O plugin detecta e aceita ambos os formatos automaticamente. Você pode usar o formato que preferir, e o sistema converterá internamente.
</Aside>

## Implementação Front-end

### Função de Parsing

```javascript
// script.js
function parseLocaleFloat(value) {
  const str = String(value).trim();
  if (!str) return 0;
  
  // Detecta se usa vírgula (PT-BR) ou ponto (EN-US)
  const hasComma = str.includes(',');
  let normalized = str;
  
  if (hasComma) {
    // PT-BR: remove pontos (milhares), troca vírgula por ponto
    normalized = str.replace(/\./g, '').replace(',', '.');
  } else {
    // EN-US: remove vírgulas (milhares), mantém ponto
    normalized = str.replace(/,/g, '');
  }
  
  const num = parseFloat(normalized);
  return isNaN(num) ? 0 : num;
}
```

### Formatação de Saída

Para exibir valores de volta ao usuário preservando o formato original:

```javascript
function formatLikeOriginal(number, originalString) {
  const str = String(originalString).trim();
  const hasComma = str.includes(',');
  
  // Detecta precisão decimal do original
  const parts = str.split(hasComma ? ',' : '.');
  const decimals = parts[1] ? parts[1].length : 0;
  
  // Formata com mesma precisão
  const formatted = number.toFixed(decimals);
  
  // Troca ponto por vírgula se original usava vírgula
  return hasComma ? formatted.replace('.', ',') : formatted;
}
```

**Exemplos:**

## Implementação Back-end

### Sanitização PHP

```php
// wc-product-creator.php
private function sanitize_row_patch($patch, $row) {
  $sanitized = [];
  
  foreach ($patch as $key => $raw_val) {
    // Verifica se é campo numérico
    if ($type === 'number') {
      if (is_numeric($raw_val)) {
        $sanitized[$key] = floatval($raw_val);
      } elseif (is_string($raw_val)) {
        // Normaliza vírgula PT-BR para ponto
        $normalized = str_replace(',', '.', $raw_val);
        if (is_numeric($normalized)) {
          $sanitized[$key] = floatval($normalized);
        } else {
          // Valor inválido, remover do patch
          continue;
        }
      }
    }
  }
  
  return $sanitized;
}
```

**Fluxo de conversão:**

```php
// Entrada: "41,5" (string com vírgula)
$raw_val = "41,5";

// Passo 1: Detecta que é string
is_string($raw_val); // true

// Passo 2: Substitui vírgula por ponto
$normalized = str_replace(',', '.', $raw_val); // "41.5"

// Passo 3: Verifica se é numérico
is_numeric($normalized); // true

// Passo 4: Converte para float
$sanitized[$key] = floatval($normalized); // 41.5
```

## Limitações

### Ambiguidade em Valores Simples

**Problema:** `1.234` pode ser interpretado como:
- PT-BR: mil duzentos e trinta e quatro (1234)
- EN-US: um ponto dois três quatro (1.234)

**Solução atual:** Se não há vírgula, assume formato EN-US (ponto é decimal).

**Contorno:** Use vírgula explicitamente para PT-BR: `1234,0`

---

### Não Suporta Outros Locales

Apenas PT-BR e EN-US são suportados. Outros formatos (ex: espaço como separador em FR) não funcionarão.

---

### Formatação de Saída Pode Não Coincidir

Se usuário digita `10` (sem decimais) e sistema calcula `10.5`, a formatação de saída pode não preservar perfeitamente o "estilo" original.

## Extensão Futura

### Detecção Automática de Locale

Usar configuração do WordPress:

```javascript
const locale = document.documentElement.lang; // 'pt-BR' ou 'en-US'

function parseLocaleFloatAuto(value) {
  if (locale === 'pt-BR') {
    return parseLocalePTBR(value);
  } else {
    return parseLocaleENUS(value);
  }
}
```

### Biblioteca de Internacionalização

Usar `Intl.NumberFormat` do JavaScript:

```javascript
const formatter = new Intl.NumberFormat('pt-BR', {
  minimumFractionDigits: 1,
  maximumFractionDigits: 3,
});

formatter.format(10.5); // "10,5" (PT-BR)

const parser = new Intl.NumberFormat('pt-BR');
// Parsing ainda requer lógica custom
```

## Compatibilidade

### Browsers

- ✅ Chrome/Edge: Totalmente suportado
- ✅ Firefox: Totalmente suportado
- ✅ Safari: Totalmente suportado
- ✅ IE11: Suportado (se polyfill de `String` presente)

### WordPress

- ✅ WP 5.0+: Funciona
- ✅ WP 6.0+: Funciona
- ℹ️ Locale do WP não afeta parsing (lógica custom independente)

### WooCommerce

- ✅ WC 6.0+: Compatível
- ℹ️ Configuração de moeda do WC não afeta (coordenadas não são preços)
